# PHASE 3 — Queue Engine mới, rolling concurrency = 10

Đây là core của hệ thống.

Không chạy:

```text
1 task
→ xong
→ task tiếp
```

Mà:

```text
MAX CONCURRENCY = 10
```

Ví dụ:

```text
Task 01 ───── running
Task 02 ───── running
Task 03 ───── running
...
Task 10 ───── running

Task 11 ───── waiting
Task 12 ───── waiting
```

Khi:

```text
Task 04 completed
```

thì ngay lập tức:

```text
Task 11
→ running
```

Không chờ cả batch 10 hoàn thành.

### Scheduler

Logic:

```text
while queue active
AND activeCount < maxConcurrency

→ lấy pending task tiếp theo
→ dispatch
```

Config:

```env
BYTEPLUS_MAX_CONCURRENCY=10
```

Không hard-code sâu trong worker.

# PHASE 23 — Recovery architecture cho paid API

Hiện tại Mock nhưng phải chuẩn bị đúng architecture.

Nếu task:

```text
providerTaskId == null
```

server restart:

```text
→ pending
→ submit lại sau
```

Nếu:

```text
providerTaskId != null
```

thì:

```text
KHÔNG submit lần hai
```

mà:

```text
resumeProviderTask(providerTaskId)
```

Mock cũng phải test logic này.

Sau này tránh:

```text
1 task
→ submit BytePlus
→ server crash
→ submit BytePlus lần nữa
→ mất tiền 2 video
```
